Background背景與商業目標

台灣旅客是很大的機會；而 Tabelog 的收入主要來自餐廳——付費刊登與線上訂位手續費。

  1. 刊登月費：付費方案才能開放線上訂位，方案越貴、搜尋排序越前面
  2. 訂位手續費：餐廳依人數付費；海外旅客另付每人 440 日圓（也是防放鳥的擔保）
  3. 2025/3 期營收約 335 億日圓、年增 20.2%，官方寫明成長原因是「付費簽約店家數＋線上訂位人數」增加

→ 目標：增加簽約店家數與訂位人數

Flywheel飛輪與切入點

用戶變多 → 店家更願意上架、投廣、開放 Tabelog 訂位 → 店家變多又吸引更多用戶。

切入點：更方便找到要吃的餐廳 → 更多的訂位

這一段直接帶動「線上訂位人數」，也就是 Tabelog 的成長來源；訂位變多後，評價更真實、用戶增加，再帶動整個飛輪。

旅客找餐廳的訴求

  1. 降低踩雷風險：出國吃錯的成本比在家高，需要可信的判斷依據
  2. 想吃在地人認證的店，也想訂到百名店等熱門店
  3. 省事：不想打電話、排隊，希望線上就能訂好
  4. 飲食限制（素食、過敏原等）的資訊常常不清楚

PAIN POINT → CHANGE

旅客先排好景點才找餐廳——那就從行程出發，幫他們找順路的店。

痛點 1

帶入行程，推薦順路餐廳

旅客先排景點才找餐廳，還要自己確認順不順路、有沒有營業 → 依前後景點位置與用餐時間推薦

痛點 2

同行需求集中呈現

兒童椅、推車空間、飲食限制常要自己翻評論 → 分成「店家確認／評論提及／需要詢問」

痛點 3

並排比較、共編清單

收藏很多間後要逐間切換比較 → 並排比較價位、營業時間、交通，清單可和旅伴共編

Reference參考競品

  1. Wanderlog｜行程匯入、地圖排程 → 參考做「建立行程」
  2. Wanderlog｜景點之間的移動時間 → 參考做「依移動時間篩選」
  3. Dell 官網｜產品並排比較 → 參考做「並排比較候選」
01

主流程：從行程到訂位

建立行程（貼上文字／Google Maps 清單／手動排）→ 依用餐時段找順路餐廳 → 用移動時間篩選 → 並排比較候選、和旅伴留言 → 選定後預約。

02

介面設計

行程 Tab

入口改到底部「行程」

首頁底部新增「行程」Tab，旅行中、規劃中、已結束的行程都在這裡，並標示每餐的預約狀態。

對應痛點痛點 ①：讓行程成為找餐廳的起點

移動時間篩選

用移動時間篩掉不順路的店

可切換步行、電車、計程車，選 5／10／15 分鐘內，並可勾選「順路前往下一站」。

對應痛點痛點 ①：不用再自己確認順不順路

和旅伴留言

候選清單可共編、可討論

旅伴可以投「我想去」、寫共同筆記，並直接在候選餐廳下方留言、@ 標記。

對應痛點痛點 ③②：兒童椅等需求在這裡一起確認

到達店家

給店員看的日文訊息

抵達後顯示預約內容，並自動產生給店員看的日文句子，例如需要一張兒童椅。

對應痛點痛點 ②：同行需求一路帶到現場
